# 实验树 · 变量收益总览（Variable ROI）实现规格

> 目标对齐实验树的核心用途：①对比不同版本差异 ②记录差异变量带来的效果 ③**给出各个变量的收益总览**。
> 现状 review：已有「画布」+「折线图(性能总览)」两个视图；边已结构化记录 `变更项 [{name,from,to}]` + 自动 `perf_summary`（e2e/compute/comm 的 parent/child/delta_pct + top_movers）。**第③点完全缺失**，第②点录入一致性不足。本规格补这两块，并顺带增强对比能力。
> 改动以**前端为主**：聚合所需数据（edges 的 variables + perf、nodes 的指标）`GET /api/projects/{pid}/experiments` 已全部返回；图表用已加载的 Chart.js v4。除非另注，**不需要后端改动**。
> 范围：`web/static/app.js` 的 `ExperimentTree`、`web/static/style.css` 的 `.exp-*`。

---

## 0. 核心设计难点：归因（先定规则，后面都依赖它）
一条边可能**同时改多个变量**，而自动算出的 delta 是这些变量的**组合效果**，无法干净地分给单个变量。因此收益总览必须区分：
- **单独变更边（isolated）**：该边只改了 1 个变量 → 其 delta 可干净归因给这个变量。**这是收益榜的可信来源。**
- **组合变更边（combined）**：该边改了 ≥2 个变量 → 不假装拆分，单独归到「组合变更」分组展示，仅作参考。
- **规则**：变量收益榜的"平均/总收益"**只统计 isolated 边**；combined 边只计数并单列。每个变量行同时显示"单独应用 N 次 / 组合出现 M 次"，让用户知道可信度。

## A. 变量收益总览视图（P0，核心新功能）

### A1 入口
- [ ] 视图切换从「画布 / 折线图」扩展为「画布 / 折线图 / **变量收益**」（沿用现有 `viewMode`，新增值 `'roi'`）。
- [ ] 共用已加载的 `nodes/edges`，切换不重新请求。

### A2 指标选择（复用折线图的主指标口径）
- [ ] 顶部主指标下拉，默认 `e2e_ms`（端到端，最能代表"收益"）；可选 `compute_ms`、`comm_ms`。
- [ ] 收益方向：时间类**负 delta = 收益（变快）**。展示统一成"收益为正"的直觉：收益值 = `-(child-parent)`（即省下的 ms），正=好。

### A3 聚合（前端纯函数，按变量聚合 isolated 边）
对每条 edge：解析 `variables`（已是 `[{name,from,to}]`）与 `perf.metrics[选定指标]`。
- [ ] 跳过 `perf` 缺失/`incomplete` 或该指标 `delta_pct==null` 的边（计入"无法评估"计数）。
- [ ] **按变量名 `name` 聚合**（默认视图），每个变量一行：
  - 单独应用次数（isolated 边数）、组合出现次数（combined 边数）
  - **平均收益**、**总收益**（ms 与 %，仅 isolated 边）
  - **命中率**：isolated 边里"带来收益(变快)"的占比
  - **最佳一次**：单次最大收益及其来源边（可点击跳转/高亮）
- [ ] **可切到按"具体变更"聚合**（`name: from→to` 为 key），更精确（同一变量不同取值效果不同）。提供「按变量 / 按具体变更」切换。
- [ ] 排序：默认按总收益降序；列头可排序。

### A4 展示
- [ ] **收益排行表**（主体）：列＝变量 / 单独次数(组合次数) / 平均收益 / 总收益 / 命中率 / 最佳一次。数值 `tabular-nums`。
- [ ] **横向条形图**（表上方或并列）：每个变量一根条，长度=总收益(或平均收益，可切)，正收益绿、负收益红（对齐 app 语义色 `--green/--red`，与画布/折线图一致）。
- [ ] **「组合变更」分区**：单列 combined 边（改了哪些变量、整体 delta），标注"组合效果，未拆分到单变量"。
- [ ] 顶部摘要卡：项目内"变量种类数 / 可评估边数 / 收益最高变量 / 退化最多变量"。
- [ ] 空态：没有任何带变量的边时，提示"在标记优化关系时填写『变更项』，这里会自动汇总各变量收益"。

### A5 交互
- [ ] 表格行/条形点击 → 高亮画布中用到该变量的边（切回画布并 highlight），或就地展开该变量涉及的边明细（边名、收益、跳转 job/对比详情）。
- [ ] 行内"最佳一次"链接 → 对应边详情 / `compare_job_id`。
- [ ] hover 行显示该变量的 from→to 取值分布（出现过哪些 from→to）。

## B. 让变量可聚合：录入一致性（P0，否则 A 的聚合会碎）
自由文本录入会让同一变量分裂成 `dtype` / `data type` / `dt`，导致收益榜失真。
- [ ] 「变更项」录入的**变量名加 `datalist` 自动补全**：候选来自本项目已存在的变量名（从已加载 edges 收集去重）。
- [ ] 聚合时做**轻量归一**：`name` 用 `trim` + 大小写不敏感匹配做归并键，但**展示保留原始写法**（取最常见写法）。
- [ ] from/to 同样 `trim`；空值按"未填"处理，不参与"具体变更"分组。
- [ ] （可选）建边/改边保存时对变量名做 `trim`，避免前后空格制造重复。

## C. 增强对比能力（P1，服务目的①）
- [ ] **任意两节点对比**：画布/折线图选中一个节点后，提供「与…对比」选择另一个节点 → 走现有 compare 流程（即便两者非父子关系），打开 A/B 详情。复用 `compare_job_id` 机制：若该对比不存在则触发生成、存在则直接跳。
- [ ] **多版本指标表**：在变量收益视图或单独 tab 给一张"所有节点 × 关键指标(e2e/compute/comm/kernel)"的可排序表，一眼对比所有版本；行可跳 job、可标记 baseline/最优。

---

## D. 边界与正确性
- [ ] 多变量边的 delta **绝不**平均/硬拆到单变量（避免误导）；只走 §0 的 isolated/combined 规则。
- [ ] isolated 边数为 0 的变量（只在组合里出现）：在表中显示但"平均/总收益"标"—（仅组合出现）"。
- [ ] 指标缺失/`incomplete` 边统一计入"无法评估"，并在摘要提示数量。
- [ ] 数值：ms 两位小数、% 一位小数、命中率百分比；`tabular-nums`。
- [ ] 深浅主题：表格/条形/网格用现有 CSS 变量，绿=`--green`/红=`--red`，与画布、折线图统一。

## E. 验收
- [ ] 新增「变量收益」视图，按变量给出 单独/组合次数、平均/总收益、命中率、最佳一次，可按"变量 / 具体变更"切换、可排序。
- [ ] 收益榜只用 isolated 边计算；combined 边单列且标注"未拆分"。
- [ ] 主指标可在 e2e/compute/comm 间切换，收益方向直觉正确（变快=正收益=绿）。
- [ ] 变量名录入有自动补全；`dtype` 不会因大小写/空格分裂成多行。
- [ ] 行/条点击能定位到相关边（高亮画布或展开明细）；最佳一次可跳详情。
- [ ] 任意两节点可发起对比；多版本指标表可排序、可跳转。
- [ ] 深浅主题、无 console error；`pytest tests/test_web_api.py` 仍全过（纯前端不应影响）。

## F. 范围与不动项
- 前端优先：`app.js`(`ExperimentTree` 新视图 + 聚合纯函数)、`style.css`(`.exp-*`)；图表用 Chart.js v4。
- 聚合数据 GET 已返回（edges.variables + edges.perf + nodes 指标），**默认无需后端改动**。
- 仅"建边/改边时 trim 变量名"（B 最后一条，可选）会碰一点后端校验；如不做则纯前端归一也可接受。
